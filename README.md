# Poziomki DB

Poziomki DB is a community database of recumbent bicycles, tadpole and delta trikes, quads, handcycles, and velomobiles. The public project contains the canonical catalog, a generated runtime database, validation tools, and a Tampermonkey interface.

## Data principles

- Truth is more important than completeness.
- A missing or unsupported value stays `null` and is displayed as unknown.
- A source URL alone is not proof that a value was verified.
- Populated technical values need evidence and a verification status.
- Conflicting sources are reviewed instead of being silently overwritten.
- Legacy `kg` values are preserved as `legacy_load_kg`; they are not automatically treated as rider weight, system weight, or rack load.

## Essential model fields

The main model view is designed to show these fields without expanding a record:

- vehicle type;
- front and rear wheel size;
- curb weight;
- maximum rider mass;
- maximum system mass;
- maximum rack load;
- lifecycle status;
- verification status.

Unknown values remain visibly empty.

## Repository structure

- `data/catalog.json` — canonical, human-reviewed catalog. Edit this file.
- `data/catalog.schema.json` — schema and essential-field contract.
- `data/migration-manifest.json` — immutable baseline and rules for the 524-record migration.
- `data/db.json` — generated runtime database consumed by the client. Do not edit this file directly.
- `data/reconciliation.json` — generated report of differences between the canonical catalog and legacy producer files.
- `producers/` — legacy per-manufacturer working files. They are not canonical and are not merged automatically.
- `tools/build-db.mjs` — validates the catalog and generates `data/db.json`.
- `tools/reconcile-db.mjs` — regenerates the legacy-data reconciliation report.
- `tools/lib/` — catalog validation, migration, runtime mapping, and reconciliation logic.
- `tests/` — zero-dependency Node.js tests.
- `dist/poziomki.user.js` — Tampermonkey client. During the write-path migration it keeps moderation API records authoritative, enriches them with canonical technical fields from GitHub, and falls back to GitHub/cache read-only if the API is unavailable.
- `.github/workflows/validate.yml` — automated validation on pushes and pull requests.

## Validation and build

Node.js 24 or newer is recommended. No package installation is required.

```bash
node --test
node tools/build-db.mjs --check
node tools/reconcile-db.mjs --check
node --check dist/poziomki.user.js
```

After an approved catalog change:

```bash
node tools/build-db.mjs --write
node tools/reconcile-db.mjs --write
node --test
```

`--check` never writes files. `--write` validates the complete catalog before replacing generated output.

## Adding or correcting a model

Edit `data/catalog.json`, not `data/db.json` or a legacy file in `producers/`.

A model with unknown technical values uses `null`:

```json
{
  "id": "manufacturer--model",
  "producer_id": "manufacturer",
  "name": "Model",
  "type": "tadpole",
  "status": "unknown",
  "verification_status": "needs_review",
  "wheels": {
    "front_in": null,
    "rear_in": null
  },
  "curb_weight_kg": null,
  "limits": {
    "rider_kg": null,
    "system_kg": null,
    "rack_kg": null
  },
  "legacy_load_kg": null,
  "url": "https://manufacturer.example/model",
  "arch": false,
  "offroad": false,
  "check": true,
  "sources": [
    {
      "url": "https://manufacturer.example/model",
      "kind": "official",
      "retrieved_at": "2026-11-24",
      "quote": "Exact source wording that supports the recorded value."
    }
  ]
}
```

Use `verification_status: "verified"` only when the source evidence supports the populated fields. If a statement applies to a whole product line, do not copy it to every model without model-specific evidence.

## Legacy producer files

The `producers/` directory contains older working data and currently differs from the canonical catalog. The reconciliation report identifies:

- models found only in producer files;
- models found only in the catalog;
- common models with changed fields;
- duplicate producer/model keys;
- possible naming aliases.

These differences are review inputs, not permission to merge automatically.

## Tampermonkey installation

1. Install [Tampermonkey for Chrome, Edge, or Opera](https://chrome.google.com/webstore/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo) or [Firefox](https://addons.mozilla.org/en-US/firefox/addon/tampermonkey/).
2. Install the script from [Greasy Fork](https://greasyfork.org/pl/scripts/577223-poziomki-db-v3-0-fleet-edition).
3. Open `google.com` or `google.pl` and expand the Poziomki DB panel.

## Disclaimer

Specifications may be incomplete, outdated, or disputed, especially for archived models. Always verify safety-relevant information, particularly load limits, against the manufacturer's current documentation before making a purchase, modification, or riding decision.
